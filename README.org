#+HTML: <p align="center"><a href="https://github.com/LispMachineLab/lispm-browser/actions/workflows/test.yml"><img src="https://github.com/LispMachineLab/lispm-browser/actions/workflows/test.yml/badge.svg" alt="test" /></a></p>

A WebKit browser in Emacs.  An Emacs built with xwidgets shows web pages in its buffers;
LispM Browser makes them a browser: its pages are tabs, each with its page's icon, it keeps the
pages visited and the pages bookmarked, it follows links and types in fields from the keyboard,
and on macOS it runs Chrome extensions, wallets such as Rabby among them.  It also keeps Emacs
from the crashes that closing pages and running their scripts could cause on macOS.  In code,
the package name and prefix are all lowercase: ~lispm-browser~.

* The LispM projects

LispM is four projects, each a repository of its own under
[[https://github.com/LispMachineLab][LispMachineLab]]:

| [[https://github.com/LispMachineLab/lispm-agent][lispm-agent]]     | LispM Agent: AI agents that run inside Emacs, their conversations org documents, their tools Elisp |
| [[https://github.com/LispMachineLab/lispm-desktop][lispm-desktop]]   | LispM Desktop: Emacs laid out as Mac OS 9's desktop, a workspace for agents, ready from the first start |
| *lispm-browser*   | LispM Browser, this repository: a WebKit browser in Emacs, with tabs, keyboard hints and Chrome extensions |
| [[https://github.com/LispMachineLab/lispm-store][lispm-store]]     | LispM Store: the catalog of applications, agents and skills LispM Desktop's App Store installs |

Each stands on its own: the browser needs neither of the others, and the agents need no browser.
LispM Desktop brings the two together, the agents in its sidebar and the browser as one of its
applications, drawn as Netscape Communicator's window was on Mac OS 9.

* What you get

- *Tabs*: every page is a tab, kept in the order it was opened, its page's icon before its
  title.  A page's tab line shows them all, a click choosing one and =+= opening another;
  =M-t= opens a tab, =M-}= and =M-{= go to the next and the previous.  Closing the last tab quits
  the browser.
- *History and bookmarks*, as Netscape Communicator kept them: every page that finishes loading
  joins the history (=lispm-browser-history-file=, the most recent ~lispm-browser-history-size~
  pages), and =M-d= bookmarks the page shown.  Bookmarks are Emacs's own (=bookmark.el=), with
  xwidget's handler, so =bookmark-jump= opens them too.  =C-l= opens an address, completed from
  both; what is typed that is no address is searched for (~lispm-browser-search-url~).  =M-b=
  opens a bookmark, =M-y= a page visited.
- *The keyboard*, as Vimium uses pages: =f= labels the links, buttons and fields in sight with a
  few letters, and typing a label follows the link, presses the button or puts the caret in the
  field; =F= opens the link in a new tab, =i= goes to the page's first field.  In a field,
  characters go in and Emacs's keys move and delete, Return submits, Tab goes on and Escape
  leaves.  Emacs on macOS cannot hand keys to a page, so they reach it through JavaScript.
- *Chrome extensions*, on macOS 15.4 and later: WebKit runs them itself, as Safari runs its own
  (WKWebExtension), in every page whose view carries its extension controller, and a dynamic
  module in Swift hands Emacs's page views that controller as they are made.  They are used as
  in Chrome.  The toolbar, at the right end of the tab line, has a button per extension pinned
  to it, its icon and badge: a click opens its popup under the button, and another closes it,
  or the extension is told it was clicked; a right click shows its menu (unpin, options,
  manage, remove).  The Extensions button after them, a puzzle piece, opens the menu of them
  all: each running extension, Pin to Toolbar, the Chrome Web Store, Load Unpacked (as Chrome's
  developer mode does) and Manage Extensions.  An extension not pinned shows on the toolbar
  while its popup is up.  The page of extensions, =lispm://extensions= (=M-x
  lispm-browser-extensions=), as Chrome's =chrome://extensions=, has a card for each, to turn it
  on and off, see what it may do, reload or remove it, with Load unpacked and Open Chrome Web
  Store at its top.  On an extension's page in the Chrome Web Store, Add to LispM stands where
  the store's Add to Chrome did (that one is Chrome's and works in Chrome alone): it is fetched,
  its signature checked and what it will be able to do asked first, and it comes pinned.  From
  the keyboard, =M-e= presses a button, its popup hanging under it, the page's buttons take
  the hints (=f=), and each action is a command: =M-x lispm-browser-extensions-install= adds one
  by its store link or id (=-install-shown= the one whose store page is shown),
  =-load-unpacked= one from a folder, =-pin= and =-unpin= put its button on the toolbar and
  take it off, =-menu= pops up the Extensions menu, and =-list= lists them in a buffer, to
  press, open the options of (in a tab of their own), turn on and off, pin, reload or remove.
  Their tabs are the browser's pages, their questions are asked in the minibuffer, and they live
  in =lispm-browser-extensions-directory=.  Most of the module is ported from
  [[https://github.com/driceroland/Search][Search]], a WebKit browser for macOS, with the script
  Search puts in every extension to fill in the Chrome APIs WebKit lacks (notifications,
  offscreen documents, a worker's WebSockets, user scripts, the side panel as a tab…) and to
  mend where WebKit behaves otherwise, so heavy extensions such as the Rabby wallet run: its
  worker, its page provider (=window.ethereum=), its popup.  A window an extension opens of its
  own, a wallet's approval of a transaction, is a Mac window whose page takes the keyboard.
  Bookmarks, history and downloads stay the browser's (an extension finds them empty), and no
  app on the Mac is spoken to (native messaging).  An Emacs started with
  =LISPM_BROWSER_WEBEXT_VERBOSE= set lists what extensions write to their consoles as errors
  and warnings with their errors, for finding out why one fails.
- *Pages that do not take Emacs down*.  On macOS (Emacs 31.1, the NS build), closing a page
  could crash Emacs, and so could a page script's callback: WebKit holds pointers to Lisp
  objects the garbage collector does not see.  The browser keeps a closed page's xwidgets from
  the collector until WebKit is done with them, drops the late events of closed pages, and keeps
  every script's callback until WebKit calls it (~lispm-browser-run-script~).

* Installation

Requires Emacs 30.1 or later built with xwidgets (on macOS, the NS build; elsewhere, GTK with
WebKitGTK).  Chrome extensions need macOS 15.4 or later and Swift (Xcode or its command line
tools), to build their module the first time one is added.

#+begin_src emacs-lisp
(package-vc-install "https://github.com/LispMachineLab/lispm-browser")
(require 'lispm-browser)
(lispm-browser-setup)
#+end_src

or, with ~use-package~:

#+begin_src emacs-lisp
(use-package lispm-browser
  :vc (:url "https://github.com/LispMachineLab/lispm-browser" :rev :newest)
  :config (lispm-browser-setup))
#+end_src

Then =M-x lispm-browser= shows the browser, opening ~lispm-browser-home-url~ when no tab is open,
and =M-x lispm-browser-browse-url= opens an address; set ~browse-url-browser-function~ to
~lispm-browser-browse-url~ for links everywhere to open in it.  Extensions start once Emacs has
started, so an init file can still turn them off with ~lispm-browser-extensions-enabled~.

* Keys

Command keys, as a Mac's browsers have them, where Command is Meta:

| =C-l=, =M-l=               | open an address, or search for what is typed   |
| =M-[=, =M-]=, =M-r=, =M-.= | back, forward, reload, stop                    |
| =M-t=, =M-}=, =M-{=        | a new tab, the next, the previous              |
| =M-d=, =M-b=, =M-y=        | bookmark the page, open a bookmark, open a page visited |
| =f=, =F=, =i=              | follow a link, in a new tab; type in the first field |
| =M-e=                      | press an extension's button                    |

~(lispm-browser-setup 'none)~ binds none of them, for a configuration that binds its own; the
list is ~lispm-browser-keys~.

* A look of its own

Out of the box the browser draws little: a tab line per page.  A program can draw it otherwise,
as LispM Desktop draws Netscape Communicator's window, by saying where the browser is and what
it shows:

| ~lispm-browser-window-function~     | the window showing the page                       |
| ~lispm-browser-tab-window-function~ | where a new tab opens when no window shows one     |
| ~lispm-browser-show-function~       | showing the browser                               |
| ~lispm-browser-raise-function~      | bringing it in front once it shows a page         |
| ~lispm-browser-tab-hook~            | each new tab's buffer: its tab, header and mode lines |
| ~lispm-browser-change-hook~         | the page or the tab shown changed                 |
| ~lispm-browser-redraw-hook~         | a title or a page icon changed                    |
| ~lispm-browser-before-quit-hook~    | the browser quits, its tabs still open            |
| ~lispm-browser-quit-hook~           | the browser quit, its tabs closed                 |
| ~lispm-browser-places-changed-hook~ | the history or the bookmarks changed              |
| ~lispm-browser-tab-line-end-function~ | what the tab line ends with: the extensions' buttons |
| ~lispm-browser-extensions-anchor-function~ | where an extension's button is, for its popup |
| ~lispm-browser-extensions-changed-hook~ | an extension's button, badge or pin changed |

What it draws with: ~lispm-browser-tabs~, ~lispm-browser-shown-buffer~, ~lispm-browser-uri~,
~lispm-browser-title~, ~lispm-browser-favicon~, ~lispm-browser-navigation-state~,
~lispm-browser-history~, ~lispm-browser-bookmarks~ and, for the extensions,
~lispm-browser-extensions-buttons~ (the toolbar's buttons: icon, badge and its colours, whether
the popup is up), ~lispm-browser-extensions-menu-items~ (the Extensions menu) and
~lispm-browser-extensions-button-menu-items~ (a button's own).  A button drawn with the text
property ~lispm-browser-extensions-button~ (its extension's id, or ~menu~ for the Extensions
button) is found where Emacs drew it by ~lispm-browser-extensions-button-anchor~, and a click on
it gives ~lispm-browser-extensions-event-anchor~; ~lispm-browser-extensions-press~ takes either,
for the popup to hang under the button.

* Tests

=make test= runs the ERT tests in batch, and =make compile= byte-compiles every file with
warnings as errors, leaving no =.elc= files behind; CI runs both with Emacs 30.1, 30.2, 31.1 and
the development snapshot.  =make webext-test= runs the extension module's own tests, on a Mac.
